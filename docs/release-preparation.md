# 공개 등록과 배포 연결 준비

## 등록 범위

- 포함 파일은 `public/`의 앱 HTML, 사진 크레딧 HTML, 매니페스트 및 아이콘, 테스트와 레시피 기준 해시, npm 잠금 파일, README·CHANGELOG·검토 문서, GitHub Actions 및 Netlify 설정입니다.
- 제외 파일은 원본 운영 스냅샷과 전체 복구 아카이브, 원본 사진 및 배경 파일 14개, Commons 원시 메타데이터, 구형 검증 로그, 테스트 결과 폴더, 설치 의존성, 환경 파일, 토큰 및 브라우저 데이터입니다. 외부 사진 2건은 라이선스 부여 또는 출처 표시의 근거가 확인될 때까지 렌더링에서 제외했습니다.
- 공개 후보에는 제3자 사진 바이너리가 없습니다. 외부 사진의 출처와 표시 의무는 [외부 사진 점검표](photo-license-audit.md)에 있습니다.
- 운영 스냅샷의 사진은 보관본에 남아 있습니다. 김치우동 사진은 코드에 승인 대기로 기록되어 있었습니다. 다른 로컬 사진 12개와 첫 화면 배경 1개는 생성 이미지로 표시되거나 파일 이름에 AI 표기가 있으나, 재배포 판단에 필요한 제작 기록은 확보되지 않았습니다.
- 공개 저장소 소유자는 공개 전에 기존 앱 코드·레시피 설명·아이콘을 게시할 권한도 확인합니다. 사진 라이선스는 프로젝트 전체의 라이선스가 아닙니다.

## 사용자 승인 및 로그인

1. GitHub에 로그인하고 공개 저장소 소유자(개인 또는 조직)와 이름 `recipe-lab`을 확인합니다. 공개 등록에 동의하면 이 디렉터리의 후보 파일만 빈 저장소의 `main`에 등록합니다. 원본 보관본은 별도로 유지합니다.
2. 첫 GitHub Actions 실행에서 `test` 작업의 12개 검사가 모두 통과하는지 확인합니다. `main`에는 `test`를 필수 상태 검사로 설정하고 풀 리퀘스트를 통한 병합을 사용합니다.
3. 개발 미리보기는 GitHub의 `netlify-preview` 환경에서 설정합니다. 환경 변수 `NETLIFY_SITE_ID`와 환경 비밀값 `NETLIFY_AUTH_TOKEN`을 사용합니다. 토큰을 소스나 채팅에 넣지 않습니다.
4. 테스트를 통과한 현재 `main` 커밋은 넷리파이의 `dev` 별칭에 초안으로 게시됩니다. 주소와 실행별 결과는 README의 링크에서 확인할 수 있습니다.
5. 운영 배포는 사용자 승인 후 별도로 진행합니다. 개발 워크플로의 게시 작업은 넷리파이 운영 배포를 호출하지 않습니다.

## 검증 결과

- 로컬 Chromium에서 무결성 4개와 데스크톱·모바일 브라우저 검사 8개를 통과했습니다. 레시피 JSON과 두 저장 키 주변 코드를 복구본과 비교했습니다.
- 공개 후보 압축을 별도 디렉터리에 풀어 Gitleaks 8.30.0으로 검사했습니다. 비밀값 패턴, 이메일 주소·국내 휴대전화·주민등록번호 패턴, PNG 텍스트·EXIF 메타데이터가 검출되지 않았습니다. Commons 저작자 표기는 공개된 저작자 이름입니다.
- 지정 Netlify CLI 버전의 도움말에서 배포 플래그를 확인했습니다. GitHub 원격 실행과 Netlify 실배포는 이번 단계에서 수행하지 않았습니다.
